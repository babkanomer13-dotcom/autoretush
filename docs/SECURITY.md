# Безопасность и приватность

## Никогда не публиковать

- фотографии детей в любом разрешении, включая кропы лица и миниатюры;
- EXIF, GPS, названия учреждений, фамилии, имена и исходные имена файлов;
- абсолютные пути к архиву;
- inventory, manifests, review queue и provenance;
- веса, чекпойнты, ONNX/TensorRT/TFLite-файлы;
- рабочие presets, параметры собственного стиля и production-конфиги;
- скриншоты локального интерфейса с реальными фотографиями.

`.gitignore` — только первая линия защиты. Перед каждым commit дополнительно проверяются staged-файлы, расширения, размер и содержимое.

## Публичный код и защита продукта

Публичный репозиторий не может технически защищать исходный код от чтения или копирования. Даже строгая лицензия даёт юридические условия, но не секретность. Практическая схема:

1. публично — описание, архитектурные интерфейсы, безопасные утилиты;
2. приватно — модель, losses, recipes, presets, веса и production UI;
3. релиз пользователю — собранный пакет без обучающих данных;
4. хэши и подписи релизов;
5. отдельные ключи и секреты вне репозитория.

В текущем репозитории намеренно нет open-source лицензии. По умолчанию автор сохраняет права, однако перед коммерческим распространением стоит получить юридическую консультацию и выбрать лицензию осознанно.

## Работа с архивом

- чтение source roots без записи;
- никаких переименований или перемещений исходников;
- новый датасет создаётся в отдельном каталоге;
- materialize сначала выполняет dry-run и проверку свободного места;
- частично созданный датасет помечается незавершённым и не используется в train;
- локальные журналы доступа и результаты ограничиваются владельцем компьютера.

## Временная удалённая проверка

Если владелец проверяет пары удалённо, разрешён только временный закрытый стенд:

- отдельный случайный/версионированный URL;
- HTTP-аутентификация или более сильный контроль доступа;
- `noindex`, отсутствие directory listing и запрет публикации manifest;
- только WebP-миниатюры без EXIF, псевдонимные `pair_id` вместо имён;
- результат проверки сохраняется вне web root;
- после подтверждённого сохранения результата изображения и временные архивы удаляются с сервера.

Пароль не хранится в Git, HTML или JavaScript. Временная публикация не заменяет проверку права на обработку фотографий.

## Инцидент

Если персональные данные попали в Git:

1. прекратить push/CI;
2. сделать репозиторий приватным;
3. удалить данные из всей истории, а не только последним commit;
4. отозвать опубликованные ключи;
5. считать склонированные данные уже раскрытыми и действовать по применимым требованиям.

Не открывайте публичный issue с образцами фотографий. Для отчёта используйте синтетическое изображение или текст без персональных данных.
